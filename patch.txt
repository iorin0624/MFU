MFUのチャット機能で、System通知テンプレート `join_approved` の送信者アイコンURLが反映されない不具合を修正してください。
コードを書く前に、まず既存実装を読み、原因を特定したうえで、最小差分で安全に修正してください。

【前提】
- 対象URL:
  - 管理画面: `/chat/admin/system-templates/join-approved`
  - 実表示: 参加承認時に流れる system メッセージ
- 関連しそうな既存要素:
  - `_normalize_system_sender_avatar_url`
  - `get_system_template_payload`
  - `get_system_template_sender_avatar_url`
  - `SYSTEM_TEMPLATE_DEFAULT_ICON_URLS`
  - `/chat/system-assets/<path:name>`
  - system actor の avatar 解決処理
- 現在の不具合は「保存されない」ではなく、「最終的な img src が壊れて画像取得に失敗する」系の挙動です
- 既存実装ではデフォルト値や `/mnt/mfu/app/...` の扱いが不統一で、正規化経路に穴があります

【必須要件】
1. 管理画面 `/chat/admin/system-templates/join-approved` で設定した `sender_avatar_url` が、実際の system メッセージ表示に反映されること
2. 以下の入力をすべてサポートすること
   - `https://...` または `http://...` の外部URL
   - `/chat/system-assets/...`
   - `/mnt/mfu/app/MIMOSA_Illustration/...`
   - `/MIMOSA_Illustration/...`
   - 空欄（デフォルト使用）
3. ローカルファイル指定は、最終的に **ブラウザで取得可能なURL** に正規化されること
4. 保存時・読込時・描画時で、同じ規則になること
5. 既存DBに保存済みの旧形式の値も、読込時に後方互換で表示できること
6. セキュリティ上危険なパストラバーサルは防ぐこと
7. DBスキーマ変更は不要。必要ならバリデーションや正規化ロジックのみ修正すること

【仕様を明確化する】
### 1. canonical（正規形）の定義
`sender_avatar_url` の内部的な正規形は次のようにすること。

- 外部URL:
  - `https://...`
  - `http://...`
  - → そのまま使う
- ローカル画像:
  - `/mnt/mfu/app/MIMOSA_Illustration/foo.png`
  - `/MIMOSA_Illustration/foo.png`
  - `/chat/system-assets/foo.png`
  - → すべて canonical として `/chat/system-assets/foo.png` 系に統一する
- 空欄:
  - デフォルトアイコンを指す canonical URL を返すこと
  - raw な `/MIMOSA_Illustration/pwa.png` のような未変換値を返してはいけない

### 2. デフォルト値の扱い
- `SYSTEM_TEMPLATE_DEFAULT_ICON_URLS["join_approved"]` を含むデフォルト処理も、必ず最終的にブラウザ参照可能な canonical URL になること
- 「空欄のときだけ未変換値が返る」挙動は禁止
- デフォルト値は保存時・読込時どちらでも矛盾なく扱うこと

### 3. 後方互換
既存DBに以下のような値が保存されていても表示できるようにすること。
- `/MIMOSA_Illustration/pwa.png`
- `/mnt/mfu/app/MIMOSA_Illustration/pwa.png`
- `/chat/system-assets/pwa.png`
- 外部URL
読込時に canonical に寄せて扱うこと

### 4. `/chat/system-assets/...` の配信
- `SYSTEM_TEMPLATE_ASSET_ROOT` 配下の画像を安全に配信すること
- 将来サブディレクトリを使っても壊れないよう、`<path:name>` を活かして安全に処理すること
- ただし `..` や不正パスは拒否すること
- 「スラッシュを含むだけで即404」のような雑な制限は見直し、**安全性を維持しつつ正当な相対パスは通す**方向で修正すること
- ルート外参照は絶対に許可しないこと

### 5. バリデーション
管理画面で `sender_avatar_url` に不正値が来た場合は、黙って壊れた値を保存しないこと
最低限以下を整理すること。
- 外部URLとして妥当か
- ローカル絶対パスとして許可対象か
- `/MIMOSA_Illustration/...` として妥当か
- `/chat/system-assets/...` として妥当か
- それ以外はエラー扱いにするか、少なくとも unsafe な値を通さないこと

【修正方針】
- まず既存コードを読んで、実際にどの経路で `sender_avatar_url` が保存され、どの経路で system actor の avatar に使われるかを確認すること
- 根本原因は「保存」「読込」「デフォルト」「描画」の正規化ルール不一致なので、場当たり的な if の継ぎ足しではなく、**正規化責務を1か所に寄せる**こと
- ただし大規模リファクタは不要。最小差分でよい
- 既存の system template 本文機能には影響を出さないこと
- 他のチャット画像アップロード機能や一般ユーザーアバター機能には手を広げないこと

【確認観点】
- 管理画面GETで表示される現在値が妥当か
- 管理画面POST後、再表示値が壊れていないか
- 実際の system メッセージ表示で反映されるか
- ネットワークタブで画像リクエストが200になるか
- 403/404になっていないか
- 既存の外部URL設定を壊していないか
- 未設定時に壊れた画像アイコンにならないか

【禁止事項】
- 無関係なリファクタ
- DBマイグレーション追加
- 他機能のUI改修を広げること
- テンプレート本文機能への仕様変更
- 画像URLを雑に文字列連結して、結果的にブラウザから見えないパスを返すこと
