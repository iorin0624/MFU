# インパーク予定共有サービス V1 確定仕様

本書は、利用者提示のV1仕様書と設計レビューで確定した内容を統合した実装基準です。
解釈が衝突する場合は、本書、`05_account_backend_database_decisions.md`、
`01_spec_review.md`、各詳細設計の順に確認します。

## 1. 目的

テーマパークへのインパーク予定を、X、Instagram、LINE、Discord等で共有し、友人・知人と
予定が重なる日を確認できるサービスを提供します。INPA自体にチャットやSNSタイムラインを
作らず、「誰がいつインパするか」の整理と共有に特化します。

## 2. サービス境界

- 利用者向けURL: `https://inpa.mydns.jp/`
- メール送信元: `noreply@inpa.mydns.jp`
- アプリ配置: `/mnt/mfu/app/inpa`
- DB: `inpa_db`
- MFUと物理サーバーは共用可能
- アプリ、Linuxユーザー、DBユーザー、DB、認証、Cookie、session、systemd serviceは独立
- MFU一般利用者アカウントとINPAアカウントは連携しない
- 運営管理だけMFU管理画面からInternal Admin API経由で行う

## 3. 技術構成

- Vue 3
- TypeScript
- Vite
- Vue Router
- Pinia
- JSON API
- Cookieベースのサーバーセッション
- MySQL 8.0以上
- Python / Flask 3系 / Gunicorn
- SQLAlchemy 2系 / Alembic / PyMySQL
- モバイルファースト
- 将来のPWA、push通知、別サーバー移設を阻害しない構成

## 4. アカウント

基本項目：

- メールアドレス
- Argon2id password hash
- 表示名
- Xハンドル（任意・自己申告）
- Instagramハンドル（任意・自己申告）
- Xハンドルの表示許可（初期値: 非表示）
- Instagramハンドルの表示許可（初期値: 非表示）
- 4つの公開範囲ごとの公開情報マトリクス
- 状態、作成・更新・退会日時

メールアドレスと内部IDは公開しません。プロフィール検索はV1では提供しません。

## 5. 登録・認証

```text
メールアドレス入力
-> Turnstileをサーバー検証
-> 仮登録と確認メール
-> 確認リンク
-> パスワード・規約同意・プロフィール
-> 正式ユーザー作成
-> 共有URL発行・最初の予定登録（スキップ可）
```

新規登録は管理者が発行した一度きりの招待tokenを必須とします。tokenは管理メモと有効期限を持ち、
未使用または手続中でも管理者が無効化できます。管理画面の設定で一般登録を明示的に有効化した
場合だけ、招待tokenなしの登録も許可します。仮登録は期限付きの `registration_requests` で管理します。メールアドレスの存在有無を推測できる
レスポンス差を作りません。

提供機能：

- ログイン・ログアウト
- ログイン状態保持の選択
- セッション一覧と個別失効
- 全端末ログアウト
- パスワード変更・再設定
- メールアドレス変更
- パスワード変更時の既存session失効

パスワード変更では現在のパスワードを再確認し、現在を含む全sessionを失効します。メールアドレス
変更では、新しいメールアドレスの確認完了後に変更し、新旧両方へ通知します。プロフィール更新、
プロフィールの一括公開設定、退会申請・取消の詳細は `05_account_backend_database_decisions.md` に従います。

認証情報はlocalStorageへ保存しません。

## 6. シーズン

年度やDハロ期間をコードへ固定しません。管理者が名称、開始日、終了日、有効状態を管理します。
将来、通常インパ、クリスマス、他テーマパーク等を追加できます。

## 7. インパーク予定

シーズン内には複数の注意・禁止期間を設定できます。V1の禁止期間は警告表示のみとし、
該当する予定の入力や保存を妨げません。管理者は名称、種別、期間、対象パーク、説明、有効状態を
管理します。期間は対象シーズン内に収め、同一種別・対象パークの有効期間は重複させません。
仮装禁止期間に既存の仮装予定がある場合は影響件数を管理画面へ表示しますが、既存データを
自動削除しません。

1ユーザー・1シーズン・1日につき1件です。

- 日付: 必須
- パーク: 🏰TDL、🌍TDS、🏰TDL・🌍TDS、未定、または未入力
- 入園予定時間: 任意
- 仮装情報: 任意、100文字まで
- メモ: 任意、500文字まで
- 公開対象と公開情報はプロフィールのシーズン別一括設定を適用

日付・時刻はAsia/Tokyo、システムtimestampはUTCで扱います。

## 8. プロフィールの一括公開設定

利用者はプロフィールでシーズンを選択し、次の4範囲ごとに日付、パーク、服装、メモの表示を
チェック式で設定します。

- `link`: 有効な共有URLを知っている人
- `logged_in`: INPAへログインしている人
- `mutual`: 双方が登録している人
- `private`: 本人だけ

公開範囲は `link -> logged_in -> mutual -> private` の順に累積します。広い範囲で許可した項目は、
より信頼度の高い範囲でも表示します。「すべて」はその行の4項目を一括でオン・オフするUIです。
変更は選択シーズンの既存予定に即時適用し、予定ごとの公開設定は行いません。シーズン専用設定が
ない場合は標準設定を継承し、利用者は専用設定を標準へ戻せます。

Vueで隠すだけではなく、APIが許可されたフィールドだけを返します。権限のない予定は統合
カレンダーの人数にも含めません。

## 10. 共有URL

```text
https://inpa.mydns.jp/{token}
```

- tokenはCrockford Base32のランダム16文字（80bit）
- 固定Vueルートと一致しない形式だけを共有ルートとして受理
- DBにはpepperを加えたtoken hashを保存
- 1ユーザーにつき有効なtokenは同時に1件だけとし、DBの一意制約でも保証
- URLコピー、QR表示、無効化、再発行
- 再発行後は旧URLを即時無効化
- access logではtokenをマスク
- OGにはサービス共通情報だけを掲載
- 共有HTMLはnoindex、nofollow、no-referrer

共有URLは閲覧権限であり、編集権限にはなりません。

## 11. 予定表登録と相互登録

他ユーザーを一方向で登録できます。

```text
A -> B: AがBの予定表を登録
A -> B かつ B -> A: 相互登録
```

相互状態は専用フラグを持たず、2本の登録関係から判定します。重複・自己登録は禁止します。
登録済み利用者は、共有tokenを再掲せず、ログイン関係に基づく画面から閲覧できます。

## 12. ブロック

AがBをブロックした場合：

- AからB、BからAの登録を同一トランザクションで解除
- ログイン状態では双方の予定を返さない
- 再登録と相互登録を禁止
- 匿名共有URLによる閲覧は人物同定できないため完全には防げない
- 必要に応じて共有URL再発行を案内

## 13. カレンダー

- 自分と閲覧可能な登録済み利用者の予定を月単位で統合
- 日曜始まりの万年カレンダーとして、選択シーズンと重なる月の範囲だけ前月・翌月へ移動
- シーズン開始前・終了後の日付セルはグレーアウトし、選択と予定追加を禁止
- 日ごとに🏰TDL・🌍TDS、🏰TDL、🌍TDS、未定の件数を色分け表示し、0件は表示しない
- 日付を選択すると閲覧可能な利用者カードを表示
- 選択日を引き継いで予定を追加し、保存後は同日のカレンダーへ戻る
- シーズン・本人・特定人物で絞り込み
- 非公開予定を件数へ含めない
- 予定作成・更新APIでも選択シーズンの期間外日付を拒否

## 14. スパム・不正利用対策

- 登録時Turnstile必須、サーバー側検証
- 登録、ログイン、メール再送、再設定、共有URL、登録、ブロック、通報のRate Limit
- IP単独の自動永久BANは行わない
- IP、IPv6 prefix、メール、アカウント、端末、操作速度を組み合わせる
- ハニーポットと不自然に短いフォーム送信の検出
- 不審時の追加Turnstile
- 通報、利用停止、セキュリティイベント

## 15. システムメール

- メール確認
- パスワード再設定
- メールアドレス変更
- セキュリティ上重要な変更
- アカウント停止・運営通知

DBキューと独立workerで送信し、失敗時は再試行します。宛先とテンプレート値は送信中だけ暗号化して
保持し、履歴には宛先ハッシュ、種別、結果を残します。SPF、DKIM、DMARCは本番公開の前提です。

## 16. MFU管理

MFU管理画面から以下を操作します。

- ダッシュボード・統計
- ユーザー検索・詳細
- 停止・解除・全session失効・退会対応
- 予定確認・問題予定削除
- share token失効
- 登録・相互・block関係確認
- 通報対応
- mail送信履歴・失敗再送
- login・security・Turnstile・Rate Limit確認
- season管理と、各season内の禁止・注意期間管理
- admin監査ログ

MFUはINPA DBへ直接SQLを発行しません。同一サーバーではUnix domain socket + HMAC署名の
Internal Admin APIを使用します。

## 17. 退会

```text
退会申請
-> 全session失効
-> share token無効化
-> 予定非公開
-> 登録関係解除
-> 30日間の取消猶予
-> 完全削除または不可逆匿名化
```

猶予中は通常ログインを許可せず、確認済みメールアドレスへ送った期限付き取消トークンで取り消します。
取消後も旧共有URLは復活させません。

ログ保存期間と例外はプライバシーポリシーへ明記します。

## 18. デザイン

- Disney公式と誤認されない独自ブランド
- 公式ロゴ、キャラクター画像、公式書体を無断使用しない
- iOS Safari、Android Chrome、X・Instagram・LINE内ブラウザーを優先
- 色だけに依存しない状態表示
- design tokenと共通Vue componentで将来の全面変更に対応

## 19. V1対象

独立アカウント、メール認証、認証・session、プロフィール、予定、公開制御、短縮URL、予定表登録、
相互判定、block、統合calendar、Turnstile、Rate Limit、MFU管理、Internal Admin API、監査、season、
通報、退会をV1に含めます。

## 20. V1対象外

チャット、DM、GPS、リアルタイム位置、SNSタイムライン、公開プロフィール検索、SNS OAuth、push通知、
プロフィール画像、ネイティブアプリ、項目単位の個別公開権限は将来拡張です。
