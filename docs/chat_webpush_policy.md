# Chat Web Push運用ポリシー（iOS Safari / PWA前提）

## 目的

iOS（Safari/PWA）ではPush配達が遅延し得るため、Pushを「呼び鈴」と位置づけ、
以下を満たす通知体験を目標とする。

- 遅延しにくい（Priority/TTL/連投抑制）
- 遅延しても害が少ない（Topic置換・鮮度管理）
- 開けば必ず追いつく（アプリ側再同期）

## サーバ送信方針

- `Urgency`
  - チャット通知は `high` を標準。
  - Urgencyは優先ヒントであり、OS都合による遅延は解消保証しない。
- `TTL`
  - チャット新着は短TTL（デフォルト60秒、環境変数で調整）。
  - 重要システム通知は長TTL（デフォルト6時間）。
- `Topic`
  - 同カテゴリ通知の置換を行う。
  - ルーム通知は room_id 由来、DM通知は dm UUID 由来の短いtopicを使う。
- `連投抑制`
  - 同一ターゲット・同一topicに対し短時間連投を抑制する。

## クライアント（Service Worker）方針

- 既に該当ルームを表示中（visible）の場合、通知表示を抑制する。
- 通知タップ時は既存タブを優先フォーカスし、対象URLへ遷移する。
- `server_ts` を含むPushは受信時に遅延指標（`now - server_ts`）を算出し、
  デバッグ用途としてページへ送る。

## アプリ内再同期

Push遅延/欠落を前提に、画面復帰時に再同期する。

- 未読件数再取得
- 通知バッジ再取得
- メッセージ差分再取得

## 非目標

- iOS PWAでPushの常時即時配達を保証すること。
